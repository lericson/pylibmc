New exception classes for libmemcached errors that used to be raised as a
plain ``pylibmc.Error``: ``AuthFailure`` (SASL login refused: wrong password,
or no credentials for a server that requires them), ``AuthProblem`` (the SASL
login could not be attempted), ``InvalidArguments``, ``ServerAllocationError``
(the server is out of memory), ``InProgress`` and ``SystemCallError``
(libmemcached's ``MEMCACHED_ERRNO``). All are subclasses of ``pylibmc.Error``,
so existing ``except pylibmc.Error`` handlers still catch them; only code that
checks for exactly ``type(exc) is pylibmc.Error`` sees a difference.
``SocketCreateError`` is now called ``ErrorReply``: it has always meant that
the server answered ``ERROR`` (an unknown command), not a socket failure.
``pylibmc.SocketCreateError`` is still the very same class, so raising and
catching it keeps working, but using that name emits a ``DeprecationWarning``,
and tracebacks and ``repr()`` now show ``pylibmc.ErrorReply``.
